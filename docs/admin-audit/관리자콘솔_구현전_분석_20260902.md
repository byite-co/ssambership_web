**`AdminListToolbar` 파라미터 소실 — 아직 있다 (+1)**

- 툴바의 검색 폼은 `q`와 hidden `status`만 보낸다(`components/admin/AdminListToolbar.tsx:25-38`). 상태 탭·페이지 링크는 `buildAdminListUrl`이 만들고, 이 빌더는 `q`·`status`·`page`·`pageSize` 4개만 안다(`lib/admin/adminListParams.ts:82-90`).

- **community-content(추가 확인)**: `basePath`를 `` `${BASE_PATH}?type=${type}` ``로 넘긴다(`community-content/page.tsx:174`, 페이지네이션 `:338`). (a) GET 폼의 `action`에 붙은 쿼리는 브라우저가 폼 데이터로 대체하므로 검색하면 `type`이 사라져 "글" 탭으로 돌아간다. (b) `buildAdminListUrl`은 `${basePath}?${qs}`로 이어 붙이므로(`adminListParams.ts:89`) 상태 탭·페이지 링크가 `/admin/community-content?type=shortforms?status=hidden`이 되고, `parseType`(`:36-40`)은 `"shortforms?status=hidden"`을 인식하지 못해 `posts`로 폴백한다. 즉 숏폼·댓글 탭에서는 "전체" 탭(빈 쿼리)만 정상 동작한다.
- 해법은 툴바·빌더가 **임의 추가 파라미터(`extraParams: Record<string,string>`)를 hidden input과 URL에 함께 실어 나르게** 하는 것 하나로 두 화면이 같이 고쳐진다. 건드릴 파일: `AdminListToolbar.tsx` · `AdminListPagination.tsx` · `adminListParams.ts` · `refunds/page.tsx:144-154`(자체 빌더 제거) · `community-content/page.tsx:174,338`.

### 3-3. 검색 추가 지점

- **필요한 조인**: `mentor_profiles.user_id → users.id`(FK, `supabase/migrations/20260701000000_pre_ledger_baseline.sql:121-122`). `users`·`mentor_profiles` 모두 관리자 SELECT 정책이 있다(`users_admin_select_all` `120_admin_console_fixes.sql:20-23`, `mp_admin_select_all` `:25-28`).
- **끼울 자리**: `loadAdminMentorApprovalsListPaged`의 `applyFilters`(`adminQueries.ts:654-671`)와 `runPagedListQuery`의 `select("*")`(`:317`). 선택지:
  1. PostgREST 임베딩 — `select("*, users!inner(full_name, email, nickname)")` + `.or("full_name.ilike…,email.ilike…", { referencedTable: "users" })`. 단 PostgREST `or`는 **부모 컬럼과 임베디드 컬럼을 한 `or`에 섞지 못하므로** 대학·학과 검색과 이름·이메일 검색을 한 입력창으로 합치려면 부적합.
  2. **뷰 또는 RPC** — `admin_mentor_approval_list`(mentor_profiles ⋈ users) 를 SQL로 만들고 `runPagedListQuery`의 `table`만 바꾼다. 검색 `or`가 한 테이블 안에서 끝나고, 컬럼 투영(§2-4)도 뷰에서 확정된다. **권장.** 새 SQL 1본이 필요하다(마이그레이션 pack 절차 §6 참조).
  3. 메모리 후처리 — 25건 안에서만 찾게 되므로 지시서 취지(전체 검색)에 어긋난다. 주석 `:645`가 이 방식을 암시하지만 미구현.
- **클라이언트 필터 제거 → 서버 탭 전환 시 바뀌는 파일**:
  - `components/admin/AdminMentorApprovalWorkspace.tsx`: `FILTERS` `:91-96`, `filter` 상태 `:103`, `filtered` useMemo `:106-115`, 필터 버튼 `:207-221`, `statusFilter`·`statusColumn` props `:49-50`, 표 데이터 소스 `:235`
  - `app/(admin)/admin/(console)/mentor-approval/page.tsx`: `sp.filter` `:28`, `statusFilter={filter}` `:149`
  - 서버 탭은 이미 있다(`page.tsx:62-69` → `AdminListToolbar` `:131-136`, 6탭 `pending/submitted/under_review/approved/rejected/all`). 현재는 **서버 탭과 클라이언트 필터 버튼이 동시에 렌더**되고, 서버 기본값은 `pending`(`:53`)인데 클라이언트 필터 기본값은 `all`(`:28, :103`)이라 첫 화면에서 두 컨트롤이 서로 다른 상태를 가리킨다.

### 3-4. 서류 뷰어

- **PDF 미표시의 정확한 위치**: `components/admin/AdminMentorApprovalWorkspace.tsx:451-453` — `student_id_image_url`에 대해 확장자 무관 `<img>`. 원인은 렌더러 선택이지 서명 URL 생성이 아니다(같은 함수로 만든 URL을 학교 서류는 `<iframe>` `:301-305`로 잘 띄운다).
