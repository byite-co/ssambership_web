## 5. C5 Storage 보상 — 삭제 호출 순서 증거

`lib/community/communityBoardActions.ts` 4분기(계약 §7 F4):

1. **업로드 실패** → 이번 요청에서 새로 올린 refs만 `compensateNewBoardImages(newUploadedRefs)` 삭제.
2. **확정 실패**(envelope `ok:false` — `message === null`) → 동일하게 신규 refs만 삭제. 기존 글 첨부는 건드리지 않음.
3. **전송·전파 오류**(timeout·응답 유실 — `message !== null`) → **삭제 금지**, 새 멱등키 발급 금지,
   "network" 안내 후 동일 키 재호출 유도.
4. **성공·재생**(`idempotent_replay` 무관) → 객체 유지. F5 성공 시엔 서버가 반환한
   `removed_image_refs`만 후속 삭제.

멱등키는 시도(attempt)당 1회 `crypto.randomUUID()` 생성 — 재호출 경로는 동일 키를 재사용한다.

통합검증 실측(§7 C5-2/3/4/5): 재생 재호출 전·후 Storage DELETE 0회(객체 잔존 확인),
확정 실패 시 해당 요청 신규 객체만 삭제됨, F5 후 `removed_image_refs`(1건 — 교체로 빠진
ref)만 삭제되고 유지 ref는 잔존.
