### 3.3 오류별 fail-closed 판정표

| 입력/실패 | 구 동작 | 신 동작 | reason |
|---|---|---|---|
| active | 통과 | 통과 | — |
| banned | 거부 | 거부 | banned |
| suspended + until NULL | 거부 | 거부 | suspended |
| suspended + until 미래 | 거부 | 거부 | suspended |

| 1차 query 실패 | status-only 재시도 → 실패 시 **통과** | 거부(재시도 0회) | unverifiable |
| permission 오류 | **통과** | 거부 | unverifiable |
| network/timeout(예외) | **통과** | 거부 | unverifiable |
| 응답 형식 오류(비객체·비문자 필드) | 판정 왜곡 가능 | 거부 | unverifiable |
| 탈퇴 write-block | 미검사 | 거부(ACCOUNT_DELETION_IN_PROGRESS 계열) | deletion_blocked |
| 탈퇴 RPC 실패·형식 불명 | 미검사 | 거부 | unverifiable |

- 예상 밖 오류를 계정상태 오류로 위장하지 않는다: unverifiable 은 별도 reason·재시도 안내 문구
  (ACCOUNT_SUSPENDED/BANNED 문구와 구분).
- 오류 로그: PII·토큰·원문 DB 응답 미기록(오류 코드·식별자 수준도 코어에서 반환하지 않음).

  (appSurfaceAccountGate — 기존 fail-closed) 유지, 주석의 "웹은 fail-open" 서술을 현행화.
