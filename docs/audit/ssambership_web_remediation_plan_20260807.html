Remediation Plan · 결함 110건 · 병렬 작업 순서

쌤버십 웹 결함 110건 병렬 수정 작업 순서 계획

110건 결함을 병렬로 수정하기 위한 작업 순서 계획입니다. 각 항목의 근거 파일을 추출해 파일 충돌 그래프(union-find)를 만든 결과, 공유 헬퍼 6개가 여러 도메인을 하나로 묶는 절단점(cut vertex)이었습니다. 이 헬퍼들을 Wave 0에서 먼저 확정하면 나머지가 도메인별 독립 배치로 쪼개져 8갈래 병렬이 가능해집니다. 병렬의 불변식은 '한 배치가 건드리는 파일 집합은 다른 병렬 배치와 겹치지 않는다'이며, 각 배치는 격리된 git worktree에서 작업하고 배치 끝마다 tsc·계약 테스트로 회귀 검증합니다.

병렬 작업 불변식 (버그 발생 요인 차단 규칙)

  1. 파일 비겹침 = 병렬 단위. 같은 파일을 건드리는 항목은 반드시 한 배치(worker) 안에서 순차 처리해 동시 편집 충돌·덮어쓰기를 원천 차단한다.
  2. 공유 계약 먼저. fail-closed 헬퍼·정본 유틸·뷰 노출 계약처럼 여러 도메인이 재사용하는 코드는 Wave 0에서 확정한다. 이후 웨이브는 '호출만 추가'라 충돌하지 않는다.
  3. fail-open→closed 전환은 헬퍼+직접 호출부를 같은 배치에. 헬퍼가 새 에러 상태를 돌려주면 호출부가 그것을 처리해야 하므로 분리하면 중간 상태에서 빌드가 깨진다.
  4. DEAD 코드 삭제는 배치 마지막에. 같은 파일의 다른 수정과 겹치면 삭제가 수정을 되돌린다. 독립 파일 삭제는 아무 때나 안전.
  5. DB·운영 작업은 코드와 분리한 마지막 웨이브. 원격 마이그레이션 적용·대시보드 토글은 PR 병합 후 사람 승인 경로로만 실행한다.
  6. 웨이브 경계마다 빌드 게이트. 각 웨이브 병합 후 tsc 0·계약 테스트 그린을 확인하고 다음 웨이브를 연다.

전제 · —
파일 충돌 그래프(union-find)는 각 결함의 근거 file:line에서 추출했다. 근거에는 '수정 대상'과 '비대칭을 지적하기 위한 대조 대상'이 섞여 있어, 병렬 배치는 보수적(대조 파일까지 잠재 충돌로 간주)으로 묶었다 — 과충돌은 병렬성만 낮출 뿐 병합 버그를 만들지 않는다. Wave 1의 8개 배치는 서로 파일이 겹치지 않음을 확인했고, 각 배치는 격리 worktree에서 작업 후 배치 끝에 tsc·계약 테스트로 검증한다. L6(학생 핵심)만 18건으로 커, 필요 시 랜딩/캐시 2개 sub-worker로 분할 가능(파일 비겹침 유지).
