# 앱·웹 결제 정책 분리 정본 (App–Web Payment Separation)
> 저장 위치: `docs/policy/app-web-payment-separation.md` · 기준: 웹 main(fcba7d8 이후) + 공유 Supabase(ssambership-staging) · 작성 2026-07-04
> 목적: Google Play 결제 정책 심사 대응. **앱과 웹은 같은 데이터베이스(캐시 지갑·원장)를 공유하지만, "결제 행위"는 웹에서만 일어난다**는 경계를 정본으로 고정한다. 앱·웹·스토어 등록정보가 이 문서와 어긋나면 이 문서가 우선한다.

## 1. 한 줄 원칙
캐시(1캐시=1원)는 **웹에서만 충전**되고(Toss 실결제, `/wallet/charge` 단일 진입), 앱은 **잔액·내역을 읽기만** 한다. 앱 안에는 결제 버튼도, 웹 결제로 보내는 링크·문구도 존재하지 않는다.

## 2. 왜 이렇게 나누는가
Google Play는 앱 내 디지털 재화 판매에 Play 결제 사용을 요구하고, **앱에서 외부 결제 수단으로 유도하는 것**(링크·버튼·"웹에서 충전하세요" 류 문구 포함)을 정책 위반으로 본다. 쌤버십 v1은 Play Billing을 붙이는 대신 결제 자체를 앱 밖(웹)에 두는 구조를 택한다. 데이터 계층은 하나이므로 웹에서 충전된 캐시가 앱에 즉시 반영되며, 이는 정책상 문제가 없다 — 문제가 되는 것은 오직 "앱이 결제로 안내하는 행위"다.

## 3. 경계표 — 기능별 노출 정본
| 영역 | 웹 | 앱 |
|---|---|---|
| 캐시 충전(Toss) | ✅ `/wallet/charge` 유일 진입 | ❌ 화면·버튼·링크·문구 전면 금지 |
| 구독 결제(캐시 차감) | ✅ | ❌ 결제 실행 금지 · 구독 "상태 조회"만 |
| 개별질문·맞춤의뢰 결제(escrow) | ✅ | ❌ 결제 실행 금지 · 진행 상태 조회/소통은 허용 |
| 캐시 잔액·원장 조회 | ✅ | ✅ (읽기 전용) |
| 멘토 정산 내역 조회 | ✅ | ✅ (읽기 전용) |
| 환불 "신청" | ✅ | 원칙 ❌(웹 안내) — 신청서가 결제 유도 없이 성립하면 추후 재검토 |

## 4. 앱에서 금지되는 것 (심사 리젝 사유가 되는 유형)
충전·결제 화면 및 버튼 일체. `/wallet/charge`·`/cash` 등 웹 결제 URL로의 딥링크·외부 브라우저 링크. "웹사이트에서 충전할 수 있어요", "PC에서 결제하세요", 가격표+구매 유도 조합 등 **우회 안내 문구**. 잔액 0원 상태에서 충전을 권유하는 다이얼로그. 푸시·알림으로 충전 페이지 유도. 스토어 등록 스크린샷에 결제 화면 포함. (허용되는 것: "캐시가 부족합니다"라는 **상태 표시** 자체 — 해결 방법 안내 없이 사실만 표기.)

## 5. 웹에서 유지되는 것
Toss 실연동 충전(`app/api/toss/confirm` — 금액 검증·멱등·웹훅 서명검증)과 충전 패키지 정본(`lib/cash/chargePackages.ts`: 3·6·12만 원 무보너스, 20만→22만·30만→34만 보너스). 구독·IQ·CR의 캐시 차감 결제. 상단 네비 '캐시결제' = `/wallet/charge`(레거시 `/cash`·`/payments`는 redirect 스텁). 회계 계층은 앱·웹 공통으로 `cash_ledger` append-only(RLS로 UPDATE/DELETE 거부, 쓰기는 service_role RPC만)를 유지하며, 이 문서로 인해 DB·원장 구조가 바뀌는 것은 없다.

## 6. 스토어 등록정보 문구 가이드
설명문에는 "학습 Q&A·멘토링 기록을 확인하는 앱"으로 기능을 서술하고 결제·충전·가격을 언급하지 않는다. 데이터 안전 섹션의 결제정보 항목은 "앱 내 결제 없음"으로 응답한다. 심사관 노트(있을 경우): "본 앱은 디지털 재화를 판매하지 않으며, 결제 기능과 외부 결제 유도 UI가 없습니다. 표시되는 캐시 잔액은 이용자가 웹 서비스에서 별도로 관리하는 계정 데이터의 조회입니다."

## 7. 출시 전 QA 체크리스트 (앱 빌드마다)
앱 전 화면 텍스트에서 `충전|결제|원|₩|krw|price|pay` 검색 → 결제 유도 맥락 0건 확인. 웹뷰·url_launcher 호출 대상 URL 전수 목록화 → `/wallet`·`/cash`·toss 도메인 부재 확인. 잔액 0 계정으로 전 플로우 탐색 → 충전 유도 다이얼로그 부재 확인. 딥링크 스킴 등록 목록에 결제 경로 부재. 스토어 스크린샷 세트에 금액·결제 UI 부재.

## 8. 연관 작업 크로스레퍼런스
회원 탈퇴 관련 FAQ·정책 문구 교체(현재 "이메일로 문의" 안내)는 본 문서가 아니라 **계정 삭제 스펙(`docs/plans/account-deletion-spec.md`) §4**에서 플래그 ON 배포와 동시에 수행한다. 사용자 차단은 `docs/plans/user-blocks-spec.md`. 본 문서는 결제 경계만 다룬다.
