## 6. 오너 결정 필요 항목

1. **본인인증 게이트(0-A #2)** — 래퍼에 `users.identity_verified_at` 검사를 두지 않았다(S-C 정책 "DB/RPC 레벨 가드 0" · env 플래그 종속). 웹 게이트가 운영에서 ON 이면 앱 경로만 미인증 결제가 가능하다. 넣으려면 199 의 학생 게이트 뒤 한 조건(`IDENTITY_REQUIRED`)이며 후속 마이그레이션 1본. A-4b 는 화면 진입에서 `identity_verified_at` 을 읽어 온보딩으로 보내는 것을 권고.
2. **released 개별질문 → 구독방 이전(0-A #16)** — 래퍼 밖(Storage 파일 복제). A-4b 에서 Edge Function(service_role) 또는 웹 cron 으로 분리 권고. 그때까지 앱 구독은 이전 없이 방만 생긴다(질문 기능엔 영향 없음).
3. **환불 계산 정본 이원화** — 웹 액션은 TS 그대로(지시서 원칙 7). 리뷰 C2 권고(웹도 SQL impl 호출)는 웹 PR 로 별도.
4. **해지 예약 취소(undo)** — 판정표 α9 는 "웹 위임" 권고였으나 지시서 A-2 대로 만들었다.
5. **복귀 시 플랜 전부 재활성**(201 active) — 웹 `resumeMentorActivity` 동일. 202 토글로 끈 tier 도 복귀 때 켜진다(웹엔 토글이 없어 문제되지 않던 상호작용). 유지/제외 결정.

## 7. H — "서류 없는 pending 잠금" 판정 · 제외 항목

**판정: DB 정책 갭 아님 → 보고만.** 192 는 멘토 승인 시 서류 없는 잠정 `pending` 행을 만들고, 웹 인증 화면은 `schoolStatus !== "pending"` 일 때만 제출을 허용해(`app/(mentor)/mentor/verification/page.tsx` — 최신 행 status 기준) 신규 승인 멘토가 서류를 올리려면 관리자 확정이 먼저 필요하다. 그러나 이 잠금은 **UI 규칙**이고 DB 정책(`msv_insert_own_pending` — 본인·pending·검증값 NULL)은 두 번째 pending 행 INSERT 를 막지 않는다(부분 UNIQUE 는 approved 만 · 174). 웹 UI 수정은 이 배치 범위 밖(원칙 7). A-4b 권고: 앱은 `pending AND document_storage_ref IS NULL`(잠정 행)을 "서류 없음 · 관리자 확정 대기"로 표시하되 제출을 잠그지 않는다(DB 가 허용) — 웹 UI 도 같은 예외를 두는 별도 PR 을 제안한다.

제외(지시서 §H): 연결노트 UNIQUE 해제(DB-5) · 맞춤의뢰 에스크로 · `api_app_v1` twin 일괄 생성 · 오답 표시 · 분쟁 래퍼(0-B).
