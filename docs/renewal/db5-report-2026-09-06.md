## 5. 오너 결정 필요 항목

1. **소셜 가입자의 동의 원장** — 지시서 정정 C 대로 `complete_profile` 은 `users.terms_agreed_at/privacy_agreed_at/marketing_agreed` 만 기록하고 `user_consent_records` 는 쓰지 않는다. 그러나 이메일 가입은 `zz_on_auth_user_created_consent_records`(087/187)가 같은 원장에 terms/privacy/marketing 행을 남기고, `user_marketing_consent_set_self` 도 그 원장에 append 한다 — 원장은 보호자 전용이 아니다(정정 C 의 전제와 다름). 소셜 가입자만 원장 행이 없는 상태가 법무 증빙에 문제면 후속 1본(complete_profile 에 `source 'profile_completion'` 3행 append)으로 닫을 수 있다.
2. **완성 전 `next` 우선순위** — 만 14세 미만 멘토(비현실적)는 `guardian_consent` 가 `identity_verification` 보다 먼저다.
3. **표시명 → `nickname`**, `full_name` 은 provider 이름 유지 — 실명이 필요한 경로(정산 계좌는 별도 예금주 · 본인인증은 NICE 결과)는 없다고 판단했다. `p_department_name` 은 선택('(미입력)' 폴백 · 트리거와 동일).
4. **v2/v3 의 계정 상태** — 지시서 정정 D 는 "v2 의 계정 상태 4종·삭제 진행 검사"를 전제했으나 **v2(204)는 그 검사를 갖고 있지 않다**: 코어는 `role='student'` 만 보고, 탈퇴 잠금은 지갑·원장 `adg_*` 트리거가 막지만 **banned/suspended 학생도 개별질문을 만들 수 있다**(실측 · 웹은 서버 액션 `assertAccountActive` 가 막는다). v3 는 지시대로 v2 와 동일(복제)하게 두었다. 닫으려면 v3(및 v2)에 계정 게이트 후속 1본 — v2 는 "하지 말 것" 2 라 오너 결정.
5. **레거시 `to public` 정책 5종 + `crp/cra/cro_insert`** 의 역할·당사자 미검사(§2-2 관찰 ①) — 완성 조건만 붙였다. 역할 조건 추가는 웹 서버 액션 경로 확인 후 별도.
6. **`user_marketing_consent_set_self` NOT NULL 결함**(§2-2 관찰 ②) — 웹 마케팅 동의 토글이 실제로 실패하고 있을 가능성. 별도 1본.
7. **대시보드 "Add user" 계정이 완성 전이 되는 변화**(§2-5 4).
8. **웹 리뷰 TS 정본 갱신**(§2-4) — 208 과 같은 PR/직후 웹 PR 필수(리뷰 0 이라 순서 자유).
9. **`plan_price_stats` 대상에 `is_open_for_subscriptions`·활동 상태 미반영** — 지시서 사양(approved × is_active)대로. 종료 예약 멘토는 플랜이 전부 비활성(201)이라 자연 제외되고, 휴식 중 멘토는 포함된다.
