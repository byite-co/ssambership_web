## 6. 오너가 정할 것

1. **시행일** — `REVISION_SOCIAL_LOGIN_EFFECTIVE_DATE` 값. 소셜 로그인 버튼 공개일 **이전**이어야 하고 제12조의 7일 사전 공지(공지사항)를 같이 잡는다. **순서**: 이 상수를 채운 배포 → 7일 → PR-2 소셜 버튼 공개. 반대 순서면 고지 없이 소셜 항목을 수집한다.
2. **법무 검토** — 제1조·제3조·제4조 초안 문구(특히 "제3자 제공이 아니라 제공받는 구조" 표현) · 환불 제2조("별표 4 준용" 표현 · 구 "7일 이내 청약철회" 문구를 없앤 것 — 전자상거래법 권리는 intro·약관 제9조에서 계속 보장) · 약관 제5조 3항 "만 14세 미만의 아동은 서비스에 가입할 수 없으며" ↔ 방침 제9조·`minor-consent`·`complete_profile` `guardian_consent` 경로(만 14세 미만 가입 허용 + 법정대리인 동의)가 **서로 다르다**(이 세션 범위 밖 · 정정 권고).
3. **동의 원장 버전 승격 시점** — `MINOR_CONSENT_VERSION`(`lib/auth/minorConsentPlaceholders.ts`) `legal-placeholder-2026-06-20` → 확정 버전. 법무 확정 후 DB-6 이후 별도 작업이며, 187/206 `user_consent_signup_impl` 의 기본 version 리터럴과 앱 `complete_profile` 호출도 같은 값으로 승급해야 한다(이 세션 0).
4. **카카오 이메일 scope**(DB-5 §2-5 1) — 켜지 않으면 방침의 "이메일은 수집되지 않을 수 있음"과 §1 #3 문구가 실제 경로가 된다. 켜면 §1 #3 첫 문장 삭제.
5. **`PROCESSORS` Supabase 위탁 업무 문구** — 현재 "클라우드 인프라·데이터베이스·파일 저장". "회원 인증(이메일·소셜 로그인 처리)" 을 덧붙일지(`lib/legal/companyInfo.ts` · 범위 밖).
6. **연결노트 "작성만"(§1 #6)** 은 PR-2 가 웹 수정·삭제 경로(`questionRoomActions.ts` · RLS 085)를 실제로 닫는지 확인한 뒤 안내서에 반영.
7. **멘토 사정 중단 환불** — 웹 TS 에 `mentor_suspended`(잔여 100% 일할) 모드와 `finalizeMentorTermination` 이 있으나 `refund` 페이지엔 문구가 없고 약관 제19조 2항은 "다음 결제일에 종료"로 다르다. 이 PR 은 학생 자발 환불(DB `refund_estimate` 범위)만 맞췄다.
8. **관리자 3명 동의 원장 부재** 등 DB-5 §5-3 잔여 결정은 그대로.
